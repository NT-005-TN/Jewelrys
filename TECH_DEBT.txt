ЗАКРЫТЫЕ ПРОБЛЕМЫ

Безопасность и сессии
- Секреты вынесены из исходников, настройка через окружение и .env.example.
- Добавлен отсутствовавший HTTP API аутентификации с валидацией.
- JWT access/refresh различаются по назначению; subject — userId, есть jti и version.
- SHA-256-хеш refresh хранится в PostgreSQL. Проверка и ротация под блокировкой
  пользователя в той же транзакции: два запроса не принимают один старый refresh.
- Новый вход, выход, смена пароля, блокировка и смена роли отзывают прежние сессии.
  Проверка актуальной версии делается для каждого нового защищённого запроса.
- Блокировка/срок действия аккаунта проверяются в фильтре; пароль повторно проверяется
  под блокировкой при входе, чтобы не пропустить одновременный сброс пароля.
- Токены подтверждения и сброса читаются под блокировкой и используются один раз.
- Запрос восстановления неизвестного email не раскрывает наличие пользователя.
- Лимит запросов использует атомарный Lua; произвольные proxy-заголовки не доверенные.
- Неиспользуемая полиморфная конфигурация сериализации кеша отключена.

Заказы и данные
- Исправлена покупка последней единицы товара.
- Покупка, возврат и ручная правка используют блокировку товара. При нескольких товарах
  единый порядок по ID снижает риск взаимных блокировок. Отмена блокирует заказ.
- Повторная отмена/установка того же статуса идемпотентна.
- Добавлен COMPLETED -> DELIVERED, закрыт разрешающий fallback для неизвестного статуса.
- Номер заказа, созданный DEFAULT БД, возвращается уже в ответе создания.
- Неполный заказ откатывается целиком, включая изменение остатка.
- Смена роли больше не удаляет профиль клиента и историю заказов.
- Убрано некорректное кеширование карточек с устаревшими ценами/остатками.
- Добавлена optimistic version для пользовательской записи; ошибки конкурентного
  изменения/уникальности возвращаются как безопасный HTTP 409.
- Генерация username сохраняет кириллицу и использует случайный суффикс.

Отчёты и API
- Типы дат репозитория приведены к Instant, отображение отчётов — UTC.
- NULL-агрегаты и товары без продаж обработаны; считается число разных заказов.
- Выручка только по COMPLETED/DELIVERED, отмены исключаются. Правила в README.
- LTV агрегируется в БД без загрузки всех заказов; новые клиенты учитывают конец периода.
- Добавлена проверка периода, лимиты page/size/days, batch fetching JPA.
- HTTP 400/401/403/404/409/500 разделены. Технические сообщения БД не возвращаются клиенту.
- X-Request-ID добавлен в ответы и логи.
- Исправлен JPQL поиска клиентов, несовместимый с обновлённым Hibernate.

Почта и наблюдаемость
- Реализована HTML-форма сброса пароля и настраиваемый PUBLIC_BASE_URL.
- Токен сброса во fragment URL, затем удаляется из адресной строки страницы.
- Транзакционный email_outbox, блокировка SKIP LOCKED, SMTP timeout, повторные попытки.
  После успешной отправки тело письма очищается. Максимум 10 попыток.
- Миграции V4/V5 добавляют сессии, очередь и аудит. V1–V3 не изменены.
- Аудит основных таблиц выполняется в БД, откатывается вместе с операцией,
  исключает пароли/токены; автор определяется из контекста транзакции, иначе system.
- Добавлены health, readiness/liveness и защищённые metrics.

Сборка и сопровождение
- Spring Boot обновлён 3.2.0 -> 3.5.16, springdoc -> 2.8.17; добавлен модуль Flyway PostgreSQL.
- Удалены лишние Jakarta API, дублирование Redis, второй mail-стек и неиспользуемый Kafka.
- JWT переведён на актуальные методы библиотеки вместо deprecated API.
- Java 17/UTF-8, Compose с Redis и healthcheck, README, безопасный Docker context.
- CI выполняет unit/MVC и Testcontainers integration tests; Dependabot и dependency review.

ОСОЗНАННЫЕ ОГРАНИЧЕНИЯ
- Одна активная сессия на пользователя; старые JWT требуют повторного входа.
- Отзыв не прерывает запрос, уже прошедший проверку авторизации.
- Почта at-least-once: после SMTP success и сбоя фиксации БД возможно повторное письмо.
- Redis обязателен для защищённых лимитом маршрутов; fail-open не используется.
- Ручная правка склада задаёт абсолютное значение. Отмена DELIVERED означает возврат.
- Продуктовый отчёт ограничен 100 строками; выгрузки большого объёма — отдельная функция.
- Нагрузочное тестирование, внешний пентест и полный SCA всех транзитивных зависимостей
  не проводились. Нельзя утверждать отсутствие любых будущих ошибок или уязвимостей.
- Тестовый PostgreSQL 18 отличается от Compose PostgreSQL 15; CI проверяет версию Compose.
